### 任务 1：跨标签页退出登录后 HomePage appliedClassIds 残留

**文件：**
- 修改：`enroll-web/src/views/HomePage.vue` — `onStorageChange` 函数

**现状：** `onStorageChange` 只监听 `application_changed` key。跨标签页退出登录时 localStorage 的 `student_token` 被移除，但 HomePage 收不到通知，`appliedClassIds` 残留。

- [ ] **步骤 1：扩展 onStorageChange 监听 student_token 变化**

```javascript
// 修改前
const onStorageChange = (e) => { if (e.key === 'application_changed') loadData() }

// 修改后：同时监听 student_token 变化（跨标签页退出登录）
const onStorageChange = (e) => {
  if (e.key === 'application_changed') loadData()
  if (e.key === 'student_token' && !e.newValue) {
    // 另一个标签页退出了登录 → 清空已报名标记
    isLoggedIn.value = false
    Object.keys(appliedClassIds).forEach(k => delete appliedClassIds[k])
    Object.keys(admittedClassIds).forEach(k => delete admittedClassIds[k])
  }
}
```

1. 打开两个标签页都在首页
2. 标签页 A 点退出登录
3. 标签页 B 刷新 → 卡片应不再显示"已报名"

### 任务 2：表单手机号/身份证改完后查重状态残留

**文件：**
- 修改：`enroll-web/src/views/FormPage.vue` — `onPhoneBlur` / `onIdCardBlur`

**现状：** 用户输入手机号 A → 查重通过（绿勾）→ 清空 → 输入手机号 B → `phoneValid` 还是旧值 `true`，`phoneConflict` 没清空，导致新号码直接显示"无冲突"而不查重。

- [ ] **步骤 1：在 onPhoneBlur 和 onIdCardBlur 中，输入值变化时重置查重状态**

```javascript
// 修改前
function onPhoneBlur() {
  const ph = form.phone.trim()
  if (!ph) {
    phoneValid.value = false
    phoneConflict.value = false
    return
  }
  phoneValid.value = /^1[3-9]\d{9}$/.test(ph)
  if (!phoneValid.value) {
    phoneConflict.value = false
    return
  }
  checkDuplicate()
}

// 修改后：格式校验通过后，如果手机号和上次查重的不一样，先清冲突状态再重新查
function onPhoneBlur() {
  const ph = form.phone.trim()
  if (!ph) {
    phoneValid.value = false
    phoneConflict.value = false
    return
  }
  phoneValid.value = /^1[3-9]\d{9}$/.test(ph)
  if (!phoneValid.value) {
    phoneConflict.value = false
    return
  }
  // 手机号变了 → 先清旧冲突状态，再重新查重
  phoneConflict.value = false
  checkDuplicate()
}
```

对 `onIdCardBlur` 做同样修改——在格式校验通过后、调 `checkDuplicate()` 前先清 `idCardConflict`：

```javascript
// 修改前

  }

// 修改后
function onIdCardBlur() {
  const id = form.idCard.trim()
  if (!id) {
    idCardValid.value = false
    idCardConflict.value = false
    return
  }
  idCardValid.value = validateIdCard(id)
  if (!idCardValid.value) {
    idCardConflict.value = false
    return
  }
  // 身份证变了 → 先清旧冲突状态，再重新查重
```

### 任务 3：截止瞬间提交的提示优化

**文件：**
- 修改：`enroll-web/src/views/FormPage.vue` — `onSubmit` 函数

**现状：** 报名截止后提交，后端返回"该班级当前不在报名时间内"，但提示不够明确，用户以为系统出错。

- [ ] **步骤 1：在 onSubmit 中捕获截止报错，给更友好的提示**

在 `onSubmit` 的 catch 中，检测后端返回的错误信息，如果是时间相关则用 warning 而非 error：

```javascript
// 修改前
} catch {
  ElMessage.error('网络错误，请稍后重试')
}

// 修改后：区分"截止"和"网络错误"
} catch (e) {
  const msg = e?.message || ''
  if (msg.includes('不在报名时间') || msg.includes('已截止')) {
    ElMessage.warning('该班级报名已截止，无法提交')
  } else {
    ElMessage.error(msg || '网络错误，请稍后重试')
  }
```

但 `submitApplicationAPI` 抛出的错误不是标准 Error 带.message。需要看 api.js 里怎么处理的。实际逻辑在 `onSubmit` 的 `result.code !== 200` 分支已经处理了"提交失败"。问题在于后端返回 200 但 code 不是 200 的情况。

当前代码逻辑：
```javascript
if (result.code === 200) {
  ElMessage.success('报名提交成功！')
} else {
  ElMessage.error(result.message || '提交失败')
}
```

后端返回 `PARAM_INVALID("该班级当前不在报名时间内")` 时 code 是业务错误码，`result.message` 有值，走 `ElMessage.error`。改为区分时间相关的错误用 warning：

```javascript
if (result.code === 200) {
  ElMessage.success('报名提交成功！')
  window.dispatchEvent(new Event('application_changed'))
  router.push('/my-applications')
} else {
  const msg = result.message || '提交失败'
  // 截止/时间相关错误用 warning（黄色），更友好
  if (msg.includes('不在报名时间') || msg.includes('已截止')) {
    ElMessage.warning(msg)
  } else {
    ElMessage.error(msg)
  }
}
```

1. 手动改数据库把截止时间设为过去
2. 尝试提交报名 → 应显示黄色 warning 提示而非红色 error

### 任务 4：AppHeader 退出登录后刷新首页数据

**文件：**
- 修改：`enroll-web/src/components/AppHeader.vue` — `onLogout`

**现状：** AppHeader 退出登录后只 dispatch 事件，不跳转页面。首页的 `appliedClassIds` 虽然通过 `login_changed` 事件清空，但 `isLoggedIn` 状态可能不同步。

- [ ] **步骤 1：退出登录后 dispatch 事件已能触发 HomePage.loadData()，无需额外跳转。但确认 HomePage.onLoginChanged 中 isLoggedIn 也要更新**

看当前 HomePage 的 `onLoginChanged`：

```javascript
const onLoginChanged = () => loadData()
```

`loadData()` 会重新拉数据，但 `isLoggedIn` 的更新依赖 `localStorage.getItem('student_token')`。在 `loadData` 内部：

```javascript
if (localStorage.getItem('student_token')) {
  // 拉我的报名...
}
```

退出后 token 已删，所以 `appliedClassIds` 会被清空（开头有 `Object.keys(appliedClassIds).forEach(k => delete appliedClassIds[k])`）。但 `isLoggedIn` 在 HomePage 里是 `ref(false)`，初始值就是 false，登录态通过 token 判断而非这个 ref。所以**没有实际 bug**，只是退出后首页顶部按钮不会从"退出登录"变为"登录"——这由 AppHeader 自己的 `refreshLoginState` 通过 `login_changed` 事件处理，应该是正常的。

实际上不需要修改，只需确认 AppHeader 退出后自身 `isLoggedIn` 更新了。看 AppHeader 的 `refreshLoginState`：

```javascript
function refreshLoginState() {
  isLoggedIn.value = !!localStorage.getItem('student_token')
}
```

它监听了 `login_changed` 事件 → 会调 `refreshLoginState` → `isLoggedIn` 变 false → 按钮自动切换。这没问题。

**结论**：此任务无需代码修改，退出登录后首页数据通过 `login_changed` → `loadData()` 自动刷新。标记为已验证。

- [ ] **步骤 1：验证确认（无需改代码）**

手动测试：首页点退出 → 确认按钮从"退出登录"变"登录"、卡片从"已报名"变"立即报名"

- [ ] **步骤 2：标记完成（无需 commit）**

### 任务 5：服务器时间同步失败后阻止提交

**文件：**
- 修改：`enroll-web/src/views/FormPage.vue` — `onMounted` 和 `onSubmit`

**现状：** `syncServerTime()` 失败后 `console.warn` 继续，`trustedNow()` 降级为本地时间。用户改手机时间可绕过报名限制。

- [ ] **步骤 1：添加服务器时间同步失败标记，阻止提交**

在 script 中新增 ref：

```javascript
const serverTimeSynced = ref(true)  // 服务器时间是否同步成功
```

修改 `onMounted` 中的 `syncServerTime`：

```javascript
// 修改前
try {
  await syncServerTime()
} catch (e) {
  console.warn('[FormPage] 服务器时间同步失败，使用本地时间：', e)
}

// 修改后
try {
  await syncServerTime()
} catch (e) {
  console.warn('[FormPage] 服务器时间同步失败，使用本地时间：', e)
  serverTimeSynced.value = false
}
```

修改提交按钮 disabled 条件，加入 `!serverTimeSynced`：

```html
<!-- 修改前 -->
<el-button type="primary" size="large" class="submit-btn" @click="onSubmit" :loading="submitting" :disabled="submitting || hasConflict || !timeStatus?.canApply">

<!-- 修改后 -->
<el-button type="primary" size="large" class="submit-btn" @click="onSubmit" :loading="submitting" :disabled="submitting || hasConflict || !timeStatus?.canApply || !serverTimeSynced">
```

添加同步失败的提示，在表单顶部显示：

```html
<!-- 在 class-desc-row 后面加 -->
<el-alert
  v-if="!serverTimeSynced"
  title="服务器时间同步失败，暂时无法提交报名，请刷新页面重试"
  type="error"
  show-icon
  :closable="false"
  style="margin-bottom: 8px;"
/>
```

- [ ] **步骤 2：浏览器验证**

1. 断网后进表单页 → 应显示红色告警"服务器时间同步失败"
2. 提交按钮应为禁用状态
3. 恢复网络后刷新页面 → 告警消失，按钮可用

- [ ] **步骤 3：Commit**


```javascript

if (result.code === 200) {
  ElMessage.success('报名提交成功！')
```
