## 第一章：项目是怎么跑起来的

### 1.1 请求的一生（从学生点"报名"到数据库写入）

```
学生浏览器
    │
    ▼  POST /api/applications  (JSON body)
enroll-web (Vue, 端口 5173)
    │  Vite 代理转发 /api/* → http://localhost:8081/*
    ▼
enroll-server (Spring Boot, 端口 8081)
    │
    ├─ CorsConfig.java          ── CORS 跨域处理（允许前端 5173 访问）
    │
    ├─ JwtInterceptor.java      ── 路径 /api/admin/** 需要 JWT 验证
    │                             （/api/applications 不过拦截器，匿名可访问）
    │
    ├─ ApplicationController.java ── 接收请求，找对应方法处理
    │     │
    │     ▼
    │  ApplicationService.java  ── 业务逻辑（事务边界在这里）
    │     │  ① 校验班级存在
    │     │  ② 校验当前时间在报名窗口内
    │     │  ③ 校验没重复报名
    │     │  ④ 原子 +1 enrolled（防并发超卖）
    │     │  ⑤ 写入 applications 表
    │     │  ⑥ 返回 DTO
    │
    └─ ApplicationRepository.java ── JPA，自动生成 SQL
         │
         ▼
    MySQL 数据库（enroll_db）
```

**关键理解**：
- **Controller** = 接收请求、参数校验、调用 Service
- **Service** = 业务逻辑、事务控制（`@Transactional`）
- **Repository** = 数据库操作，JPA 根据方法名自动生成 SQL
- **Entity** = 跟数据库表一一对应的 Java 对象

## 第二章：Java Spring Boot 核心概念（新手友好版）

### 2.1 注解扫盲（看到这些要知道它们干了什么）

| 注解 | 出现在 | 是什么意思 |
|------|--------|-----------|
| `@RestController` | Controller 类上 | "这个类是接收 HTTP 请求的"，返回值自动序列化为 JSON |
| `@Service` | Service 类上 | "这个类是业务逻辑层"，Spring 自动实例化并管理生命周期 |
| `@Repository` | Repository 类上 | "这个类是数据库操作层"，JPA 会在启动时自动实现它 |
| `@Entity` | 实体类上 | "这个类对应数据库一张表" |
| `@Table(name = "xxx")` | 实体类上 | "这个类对应数据库的 xxx 表"（不写默认类名小写）|
| `@Column` | 实体类字段上 | "这个字段对应数据库一列"，可指定长度、是否可空 |
| `@Id` + `@GeneratedValue` | 主键字段上 | "这是自增主键" |
| `@Transactional` | Service 方法上 | "这个方法内的所有数据库操作要么全成功，要么全失败" |
| `@PrePersist` | 实体方法上 | "插入数据库前自动调这个方法"（用来设默认值）|
| `@Autowired` | 构造器参数上 | "Spring 自动把对应 Bean 传进来"（构造器注入更推荐）|
| `@Value("${xxx}")` | 字段上 | "从配置文件里读 xxx 的值" |
| `@Async` | Service 方法上 | "这个方法异步执行，不阻塞主线程" |

### 2.2 三层架构是什么

```
┌─────────────────────────────────────────────────────┐
│  Controller 层（controller/ 包）                     │
│  - 接收 HTTP 请求（GET/POST 参数）                   │
│  - 参数简单校验（比如 id 是否为空）                   │
│  - 调用 Service，捕获异常                            │
│  - 返回统一格式 R.ok() / R.fail()                   │
└──────────────────┬──────────────────────────────────┘
                   │ 调用
┌──────────────────▼──────────────────────────────────┐
│  Service 层（service/ 包）                          │
│  - 写业务逻辑（if/else/循环判断）                    │
│  - 事务控制 @Transactional                          │
│  - 不直接写 SQL，用 Repository 操作数据库            │
└──────────────────┬──────────────────────────────────┘
                   │ 调用
┌──────────────────▼──────────────────────────────────┐
│  Repository 层（repository/ 包）                    │
│  - JPA 根据方法名自动生成 SQL                        │
│  - findByName → SELECT * FROM xxx WHERE name = ?   │
│  - 自定义 SQL 用 @Query 注解                        │
└──────────────────┬──────────────────────────────────┘
                   │ 操作
┌──────────────────▼──────────────────────────────────┐
│  数据库（MySQL）                                     │
└─────────────────────────────────────────────────────┘
```

### 2.3 JPA 方法名自动生成规则（不用写 SQL）

```java
// Repository 里这样写方法，JPA 自动生成 SQL
public interface ApplicationRepository extends JpaRepository<Application, Integer> {

    // 方法名：findBy + 字段名 + And + 字段名
    // → SELECT * FROM ssc_applications WHERE id_card = ? AND status = ?
    List<Application> findByIdCardAndStatus(String idCard, Integer status);

    // 方法名含 In → SQL 用 IN
    // → SELECT * FROM ssc_applications WHERE id_card = ? AND status IN (?,?,?)
    List<Application> findByIdCardAndStatusIn(String idCard, List<Integer> statuses);

    // 方法名含 Like → SQL 用 LIKE
    List<Application> findByNameContaining(String keyword);
}
```

### 2.4 实体类和数据库表的映射关系

```java
@Entity
@Table(name = "ssc_applications")          // 对应哪张表
public class Application {

    @Id                                   // 主键
    @GeneratedValue(strategy = GenerationType.IDENTITY)  // 自增
    private Integer id;

    @Column(name = "id_card", nullable = false, length = 18)
    private String idCard;                // 字段名是 id_card，不是 idCard
                                          // nullable = false → 不可为空
                                          // length = 18 → VARCHAR(18)

    @Column(name = "notice_agreed", nullable = false)
    private Integer noticeAgreed;         // 数据库存 0/1，Java 用 Integer
}
```

**字段命名规律**：
- Java 用驼峰命名法：`idCard`、`classId`、`applyTime`
- 数据库用蛇形命名法：`id_card`、`class_id`、`apply_time`
- `@Column(name = "xxx")` 做映射，不写默认按规则转换

### 2.5 统一响应格式 R.java

所有接口返回同一个结构：

```json
{
  "code": 200,           // 200=成功，其他=业务异常
  "message": "操作成功", // 给用户看的提示
  "data": { ... }        // 业务数据，失败时为 null
}
```

前端判断：

```javascript
const res = await fetch('/api/applications')
if (res.code !== 200) {
  alert(res.message)  // 业务异常提示
  return
}
renderData(res.data)  // 成功，渲染数据
```

## 第三章：数据库核心表结构

### 3.1 classes 表（特色班）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键自增 |
| name | VARCHAR(200) | 班级名称 |
| period | VARCHAR(30) | 当前有效时间段（首页展示用）|
| periods | TEXT | JSON 多轮时间段（核心字段）|
| quota | INT | 名额上限（-1=不限）|
| enrolled | INT | 已报名人数（每有人报名+1）|
| is_deleted | INT | 软删除：0=正常，1=已删除 |
| category_names | TEXT | 班级类别 JSON 数组 |
| source | VARCHAR(20) | 数据来源：admin/sync |

**periods JSON 格式**：

```json
[
  {"round": 1, "period": "2026/09/01 - 2026/09/13"},
  {"round": 2, "period": "2026/09/15 08:00 - 2026/09/16 23:59"}
]
```

系统根据**当前日期**自动判断在哪个时间段，返回对应 `round`。

### 3.2 applications 表（报名记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键自增 |
| name | VARCHAR(20) | 学生姓名 |
| id_card | VARCHAR(18) | 身份证号（完整，查重用）|
| id_card_masked | VARCHAR(18) | 脱敏版（中间8位变 ********）|
| gender | VARCHAR(2) | 性别 |
| phone | VARCHAR(11) | 手机号 |
| class_id | INT | 报名的班级 ID |
| status | INT | 报名状态（见下）|
| notice_agreed | INT | 是否同意报名须知（0/1）|
| apply_time | DATETIME | 报名时间 |
| round | INT | 报的是第几轮 |
| source | VARCHAR(20) | 数据来源 |

**status 状态机**：

| 值 | 含义 | 说明 |
|----|------|------|
| 0 | 未报名 | 默认值 |
| 1 | 已报名 | 学生刚提交 |
| 2 | 已撤回 | 学生主动撤回 |
| 3 | 已录取 | 管理员录取，永久锁定 |
| 4 | 不录取 | 管理员驳回，可报其他班 |

**状态流转图**：

```
提交报名 ──→ status=1(已报名)
    │
    ├─ 学生撤回 ──→ status=2(已撤回) ──→ 可重新报名（重新变1）
    │
    ├─ 管理员录取 ──→ status=3(已录取)  ← 永久锁定，不可撤回
    │
    └─ 管理员驳回 ──→ status=4(不录取) ← 可报其他班
```

### 3.3 categories 表（班级类别）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键自增 |
| name | VARCHAR(50) | 类别名称（如"成电班"、"ACCA"）|

### 3.4 sys_config 表（系统配置）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键自增 |
| cfg_key | VARCHAR(50) | 配置项名（如"notice"）|
| cfg_value | TEXT | 配置值（JSON 字符串）|
| updated_by | VARCHAR(50) | 更新人 |

## 第四章：维护场景手册（按需查阅）

### 场景 A：我想在首页加一个字段显示

**问题**：要在班级卡片上加一个"已报名人数/enrolled"的显示

**步骤**：

3. 改 `ClassCard.vue` 加显示逻辑

**关键文件**：
```

```

### 场景 B：我想加一种新的报名状态

**问题**：要加一个"待审核"状态

**步骤**：
1. `Application.java` 实体 → 加 `STATUS_PENDING = 5` 常量
2. `ApplicationService.java` → 在状态判断逻辑里加对 5 的处理
3. 前端 `data.js` → `getClassTimeStatus` 里加对 5 的判断（如果影响卡片显示的话）

**关键文件**：

### 场景 C：我想改报名时间判断逻辑

**问题**：当前是按自然日期判断，想改成按"报名开放时间"字段判断

**步骤**：
1. 找到时间判断逻辑 → `ApplicationService.isInPeriod()`（第163-180行）
2. 这个方法解析 `period` 字符串（格式：`"2026/09/01 - 2026/09/13"`）

**关键文件**：
```

```

### 场景 D：我想加一个新接口

**问题**：低代码平台需要一个"按手机号查报名"的接口

### 场景 E：我想看某个学生有没有报过名

**问题**：运营人员说学生张三报不了名，要查原因

**步骤**：
1. 打开数据库客户端，连 `enroll_db`
2. 查 `ssc_applications` 表：
```sql
SELECT * FROM ssc_applications WHERE name = '张三' OR id_card = '身份证号';
```
3. 看 status 列：
   - status=1 → 已报名其他班（全局唯一冲突）
   - status=3 → 已录取（永久锁定）
   - status=4 → 不录取（可重新报）

## 第五章：前后端交互核心逻辑

### 5.1 前端怎么知道某班已报名（按钮变绿）

```
HomePage.vue
  │  mounted 时调用 fetchMyApplicationsMe()
  │  返回学生所有报名记录（status=1/3/4）
  ▼
appliedClassIds[classId] = true   ← 存在 appliedClassIds 里
admittedClassIds[classId] = true  ← 录取的另外存一份
  │
  ▼  通过 props 传给 ClassCard
ClassCard.vue
  │  btnClass 计算属性
  ▼
isAdmitted  → 黄色按钮"已录取"
isApplied   → 绿色按钮"已报名"（注意：status=4 不录取也是绿色）
其他        → 蓝色/灰色"立即报名"
```

**按钮颜色判断逻辑**（`ClassCard.vue` 的 `btnClass`）：

```javascript
if (props.isAdmitted)  return 'card-btn--admitted'   // 黄色
if (props.isApplied)   return 'card-btn--applied'    // 绿色
return `card-btn--${timeStatus.value.status}`        // 蓝色(报名中)/灰色(已截止)
```

### 5.2 前端怎么刷新报名状态

问题：报名成功后为什么按钮立刻变绿？

答案：通过 `application_changed` 自定义事件触发同 tab 刷新：

```
FormPage.vue 提交成功后
  │
  ▼ window.dispatchEvent(new Event('application_changed'))
HomePage.vue 监听这个事件
  │
  ▼ 重新调用 fetchMyApplicationsMe() + fetchClasses()
页面刷新 appliedClassIds → 按钮变绿
```

### 5.3 为什么有些字段数据库有但接口没返回

因为后端返回的是 **DTO**，不是 Entity。DTO 只包含需要暴露的字段。

```
ClassInfo（实体）  →  ClassDTO（出参）
Entity 全部字段       只包含需要给前端的字段
（如 is_deleted）    （已删除班级管理端单独处理）
```
