# 模块说明

特色班报名系统为**双库双端架构**，负责新生特色班报名全流程：

- 负责学生报名信息采集与提交（外网 enroll-web 学生端，仅外网库产生学生报名数据）
- 负责特色班、报名轮次、班级类别的维护与展示
- 负责管理员审核/录取/驳回（内网低代码平台管理端，NASL 数据同步回推外网）
- 负责报名须知、全局联系方式等系统配置
- 为内外网对账、查重、录取名单导出提供数据支持

⚠️ **架构要点**：外网库与内网库各自维护一套 `ssc_` 前缀同名表，**两库字段大体一致但存在若干关键差异**（详见下节）。两库间不共享主键 id，通过 `outer_id` 字段建立跨库映射（注意：**两库 `outer_id` 语义方向相反**）。

# 双库架构与差异总览

| 项目 | 外网库 `enroll_db` | 内网库 `smart_academic_affairs` |
| --- | --- | --- |
| 端 | 学生报名 H5/Web（enroll-web）+ 后端 enroll-server（Spring Boot） | 管理端（CodeWave 低代码平台，NASL） |
| 谁写报名数据 | ✅ 学生提交报名写入 | ❌ 不直接写，靠同步 |
| 谁做审核/录取 | 接收内网回推（admit/reject） | ✅ 管理员操作（NASL `dataSynchronization()` 重建后改状态） |
| 同步角色 | 被拉取方（提供 `/api/admin/applications/all`） | 主动拉取方（NASL 主链路） |
| 主键 | 各自独立自增，互不相同 | 各自独立自增，互不相同 |

**字段差异速查表**（细节见各表）：

| 差异点 | 外网 `enroll_db` | 内网 `smart_academic_affairs` | 影响 |
| --- | --- | --- | --- |
| `class_rounds.period_start/end` 类型 | `DATETIME` | `VARCHAR(50)`（存 `yyyy-MM-dd HH:mm:ss` 字符串） | 内网为避免低代码平台 DateTime 转换坑改用字符串，**跨库同步/比对时需注意格式** |
| `applications.outer_id` 语义 | 存**内网**报名记录 id（syncFromLowCode 备链路回填） | 存**外网**报名记录 id（NASL 主链路回填） | 对账/查重一律以**内网 `outer_id` = 外网报名 id** 为桥梁 |
| `classes.outer_id` 语义 | 存**内网**班级 id | 存**外网**班级 id | 同上，方向相反 |
| `enrolled` 字段口径 | 注释「已弃用」 | 注释「冗余字段」 | 结构都有该列，含义两库注释不一致，勿当权威计数 |
| `applications` 索引 | INIT 基线 3 个 + 生产增量补齐查询索引 | 仅基础 2 个（id_card、class_id） | 内网不依赖数据库索引做复杂筛选 |
| `class_rounds` 时间索引 | 有 `idx_period_start/end` | 无 | 内网 VARCHAR 时间不做 DB 区间查询 |

| status | 报名状态 | 否 | Integer | - | 是 | 0 | **0=未报名 1=审核中(已报名) 2=已撤回 3=已录取 4=未录取** |
| notice_agreed | 同意报名须知 | 否 | Integer | - | 是 | 无 | 0=否 1=是 |

### ⚠️ 双库字段差异

| 差异点 | 外网 `enroll_db` | 内网 `smart_academic_affairs` | 说明 |
| --- | --- | --- | --- |
| `outer_id` 指向 | 存**内网报名记录 id**（enroll-server `syncFromLowCode` 备链路回填） | 存**外网报名记录 id**（NASL 主链路 `dataSynchronization()` 拉全量后回填） | 日常对账、查重、同步状态比对**只用内网 `outer_id`=外网报名 id**；外网侧 `outer_id` 在主链路下基本为 NULL，不可用作对账条件 |
| 索引 | `idx_id_card`、`idx_class_id`、`idx_enrollment_year`（INIT 基线）；生产增量另补 `idx_phone`、`idx_status`、`idx_id_card_status`、`idx_class_status`、`idx_is_deleted` | 仅 `idx_id_card`、`idx_class_id` | 内网筛选走低代码平台逻辑，不依赖 DB 索引 |
| 注释口径 | 均同 | 均同 | `id_card_masked` 均为「中间8位 ***」 |

### ⚠️ 双库字段差异

| 差异点 | 外网 `enroll_db` | 内网 `smart_academic_affairs` | 说明 |
| --- | --- | --- | --- |
| `period_start` 类型 | `DATETIME` | `VARCHAR(50)` | 内网存 `yyyy-MM-dd HH:mm:ss` 字符串，**为避免低代码平台 DateTime 转换坑而设计**（见内网 INIT SQL 注释） |

| 唯一键 | `uk_class_round(class_id, round_num)` | `uk_class_round(class_id, round_num)` | 一致 |
| 实体映射 | Java `LocalDateTime` | NASL 字符串处理 | 跨库传输时外网 API 会输出为字符串，内网可直接落库 |

> 💡 跨库核对轮次时间时：外网 DATETIME 与内网 VARCHAR 内容同格式（`yyyy-MM-dd HH:mm:ss`），可字符串直接比对。

# 表关系

## 关系说明

模块内共 6 张表，两库结构平行（表前缀统一 `ssc_`）：

- `ssc_categories`（类别字典）与 `ssc_classes`（班级）为 **N:N**，通过 `ssc_class_category` 中间表关联
- `ssc_classes`（班级）与 `ssc_class_rounds`（轮次）为 **1:N**，一个班级可有多轮报名时间段
- `ssc_applications`（报名记录）通过 `class_id` 关联班级，1 条记录 = 1 个学生对 1 个班级的 1 次报名
- `ssc_sys_config`（系统配置）独立单行表，不与其他表关联
- **跨库**：内网 `ssc_applications.outer_id` = 外网 `ssc_applications.id`（对账/同步桥梁），内网 `ssc_classes.outer_id` = 外网 `ssc_classes.id`；反向同理但主链路不使用

关系：

```text
外网 enroll_db：
   ssc_categories.id ──< ssc_class_category.category_id
                                     │ class_id
   ssc_classes.id <──────────────────┘
        │ 1:N（轮次）
        ↓
   ssc_class_rounds.class_id
        ▲
        │ N:1（报名选班）
   ssc_applications.class_id  （outer_id ──→ 内网 ssc_applications.id）

内网 smart_academic_affairs：
   结构与外网平行；ssc_applications.outer_id / ssc_classes.outer_id
   指向外网对应记录 id（NASL 同步回填）
```

一对多关联示意：

```text
ssc_classes（1） ──1:N── ssc_class_rounds（N）
                        ssc_class_rounds.class_id = ssc_classes.id

ssc_categories（N） ──N:N── ssc_classes（N）
                        ssc_class_category（中间表）

ssc_classes（1） ──1:N── ssc_applications（N）
                        ssc_applications.class_id = ssc_classes.id
```
