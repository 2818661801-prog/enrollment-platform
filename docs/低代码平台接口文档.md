# 特色班报名系统 · 低代码平台 API 文档

> 版本：v1.0.0
> 日期：2026-07-03
> 基础路径：`http://<后端地址>:8081/api/admin`
> 鉴权方式：JWT Bearer Token（`Authorization: Bearer <token>`）
> 协议说明：所有"改数据库"接口只开放 **POST**，查询接口只用 **GET**

---

## 使用指南

### 第一步：获取 Token（登录）

低代码平台打开后，先调用登录接口换取 Token：

```bash
POST http://<后端地址>:8081/api/auth/login
Content-Type: application/json

{
  "username": "***REMOVED***",
  "password": "***REMOVED***"
}
```

返回的 `data.token` 即为 JWT，后续所有接口请求 Header 必须带上：

```
Authorization: Bearer <token>
```

> ⚠️ 生产环境：此接口为开发期临时账号，生产应替换为智慧教务平台 OAuth2 接入方案。

---

### 第二步：调用业务接口

登录获取 Token 后，所有 `/api/admin/**` 接口都要带 Header：

```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

以查询班级列表为例：

```bash
GET http://<后端地址>:8081/api/admin/classes
Authorization: Bearer <token>
```

返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [ ... ]
}
```

---

### 第三步：判断操作是否成功

检查响应里的 `code`：

| code | 含义 | 后续动作 |
|------|------|---------|
| 200 | 成功 | 读取 `data` |
| 4001-4006 | 业务异常 | 提示用户 `message` |
| 5000 | 系统异常 | 提示用户"系统繁忙，稍后重试" |

```javascript
// 低代码平台 JS 表达式示例
const res = fetch('/api/admin/classes', {
  headers: { 'Authorization': 'Bearer ' + token }
});
const json = res.json();
if (json.code !== 200) {
  showAlert(json.message);  // 业务异常提示
} else {
  renderTable(json.data);   // 成功，渲染数据
}
```

### 第四步：典型业务流程

#### 流程 A：新建一个班级

```
1. GET  /api/admin/categories          → 拉取已有类别（下拉框用）
2. POST /api/admin/classes             → 创建班级（选好类别 ID 后提交）
3. GET  /api/admin/classes             → 确认班级出现在列表中
```

**Step 2 的 Body 示例：**

```json
{
  "name": "CFA 特色班",
  "period": "2026/09/01 - 2026/09/13",
  "periods": "[{\"round\":1,\"period\":\"2026/09/01 - 2026/09/13\"}]",
  "quota": 40,
  "description": "CFA 特色班介绍...",
  "categoryIds": [2, 3],
  "source": "sync"
}
```

#### 流程 B：录取一批学生

```
1. GET /api/admin/applications?classId=2&status=1   → 查出某班所有已报名的学生
2. POST /api/admin/applications/admit               → 批量录取
```

**Step 2 的 Body 示例：**

```json
{
  "ids": [3, 7, 12, 18],
  "auditComment": "经审核，拟录取以上同学"
}
```

#### 流程 C：修改班级报名时间（多轮）

```
1. GET  /api/admin/classes/5                        → 确认当前时间段
2. POST /api/admin/classes/update                   → 更新整班信息（含 periods）
```

> 如果只改第二轮的时间段，单独用 `update-period` 更轻量：
> ```json
> { "id": 5, "period": "2026/09/20 - 2026/09/28" }
> ```

#### 流程 D：恢复误删的班级

班级删除后 `is_deleted → 1`，学生端不再显示。如需恢复：

```
POST /api/admin/classes/update
Body: { "id": 5, "isDeleted": 0, ...其他字段保持不变... }
```

⚠️ `update` 是全量更新，需传入班级所有字段，否则未传字段会被置空。建议先用 `GET /api/admin/classes` 查到完整数据再修改。

#### 流程 E：管理报名须知

```
1. GET  /api/admin/notice                 → 读取当前须知
2. POST /api/admin/notice/update          → 保存新须知
```

### 常见问题

**Q：为什么有的更新接口特别多（update / update-period / update-quota）？**

A：这是有意拆分的细粒度接口。低代码平台配置按钮时，可以给"改时间"和"改配额"单独绑定不同接口，比全量 `update` 更不容易出错。

**Q：软删除的数据还能看到吗？**

A：
- 班级：管理端 `GET /api/admin/classes` **包含**已删除班级（`isDeleted: 1`），可恢复
- 报名记录：软删除后 `status → 0`，列表默认不显示（可加 `status=0` 参数筛出）

**Q：并发操作会不会有问题？**

A：`enrolled`（已报名人数）是每次报名时**累加**的，不是实时计算。批量操作（admit/reject/delete）有事务保护，不会出现中间状态。

**Q：ids 参数支持哪些格式？**

A：支持两种格式：
```json
{ "ids": [1, 2, 3] }         // 数组（推荐）
{ "ids": "1,2,3" }           // 逗号分隔字符串
```

## 统一响应格式

所有接口响应结构一致：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

**失败响应示例：**

```json
{
  "code": 4005,
  "message": "id 不能为空",
  "data": null
}
```

**业务码说明：**

| code | 含义 |
|------|------|
| 200 | 成功 |
| 4001 | 班级不存在 |
| 4002 | 班级名额已满 |
| 4003 | 重复报名 |
| 4004 | 报名记录不存在 |
| 4005 | 请求参数不合法 |
| 4006 | 类别不存在 |
| 5000 | 系统繁忙 |

**字段说明：**

**多轮 periods JSON 格式：**

```json

Content-Type: application/json
Authorization: Bearer <token>
```

**Body：**

```json
{
  "key": "notice",
  "cfgValue": "{\"title\":\"报名须知\",\"conditions\":[],\"notices\":[]}",
  "updatedBy": "admin"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| key | string | ✅ | 配置项名称 |
| cfgValue | string | ✅ | 配置值（字符串） |
| updatedBy | string | 否 | 更新人标识 |

**响应：**

```json
{
  "code": 200,
  "message": "保存成功",
  "data": null
}
```

## 七、低代码平台特别说明

### 7.1 数据来源标记

每张表都有 `source` 字段，标识数据来源：

| source 值 | 含义 |
|-----------|------|
| `admin` | 管理员直接创建 |
| `sync` | 内网低代码平台同步 |

低代码平台写入时建议在 Body 中传入 `"source": "sync"`，方便后续数据溯源。

### 7.2 软删除与恢复

- **班级软删除**：`POST /api/admin/classes/delete` → `is_deleted → 1`
- **班级恢复**：`POST /api/admin/classes/update` + Body 传 `isDeleted: 0`
- **报名软删除**：`POST /api/admin/applications/delete` → `status → 0`
