## 2. 全链路冒烟逐环节（curl 实测）

### 2.1 管理员登录
```
POST /api/auth/login  {"username":"***REMOVED***","password":"***REMOVED***"}
→ {"code":200,"message":"登录成功","data":{"token":"eyJ..."}}
```

### 2.2 建班（两个，报名期覆盖当前时间）
```
POST /api/admin/classes  {"name":"smoke-test-20260921","quota":10,
  "classRounds":[{"roundNum":1,"periodStart":"2026/09/21 18:30","periodEnd":"2026/10/21 23:59"}]}
→ {"code":200,"message":"创建成功","data":{"id":8,...}}
另一班 → id=9
```

### 2.3 学生报名（4 条）
```
POST /api/applications（JSON 从文件提交，避开 Git Bash 中文编码）
→ 张三丰 id=2 班8 / 李四 id=3 班8 / 王五 id=4 班8 / 王五 id=5 班9 / 赵六（sync 新增）id=6 班8 均 code:200
```

### 2.4 查重
```
GET /api/applications/check?phone=***REMOVED***&idCard=110101***REMOVED***7&classId=8
→ {"hasPhoneConflict":true,"phoneClassName":"smoke-test-20260921",
   "hasIdCardConflict":true,"hasSameClassConflict":true}
```

### 2.5 批量录取（含 skipped）
```
POST /api/admin/applications/admit  {"ids":[2,3,999],"auditComment":"smoke admit"}
→ {code:200, message:"已录取 2 名学生（跳过 0 条）", data:{processed:2, skippedCount:0, skipped:[]}}
```
> 说明：999 不在表中，findAllById 查不到 → 不计入 processed 也不计入 skipped（v1 同款语义）。

### 2.6 批量驳回（含 skipped，关键验证）
```
POST /api/admin/applications/reject  {"ids":[4,2],"auditComment":"smoke reject"}
→ {"code":200,"message":"已设置 1 名学生为未录取（跳过 1 条）",
   "data":{"processed":1,"skippedCount":1,"skipped":["id=2 当前状态为已录取，已跳过"]}}
```
> ✅ 新架构的容错批量：不再"一条非审核中整批失败"，跳过并如实汇报原因。

### 2.7 业务裁决验证（ADR-驳回后禁止重报）
```
① 王五（id=4 已驳回）再报原班 classId=8
→ {"code":4003,"message":"未录取无法再次报名"}          ✅ 同班禁报
② 王五再报其他班 classId=9
→ {"code":200,"message":"提交成功", data:{id:5, ...}}   ✅ 他班可报
```

### 2.8 我的报名查询
```
POST /api/auth/login/sms  {"phone":"***REMOVED***","code":"666666"}  → token
GET  /api/applications/me  (Bearer token)
→ 两条记录：班8 status=4（驳回，auditComment=smoke reject）+ 班9 status=1
```

### 2.9 sync/applications 三态同步（本轮移植核心）
```
POST /api/admin/sync/applications
① 新增：赵六 idCard=110101***REMOVED***7 classId=8  → {inserted:1}
② 更新：王五 idCard=110101***REMOVED***5 classId=8 status=4 → {updated:1}
③ 防重：赵六（班8已有有效报名）再推班9  → {skipped:1}   ✅ 防重生效
④ 显式软删：王五 classId=9 isDeleted=1  → {updated:1}
```
落库核实（mysql 查询 ssc_applications）：
| id | 姓名 | 班 | status | is_deleted | source |
|----|------|----|--------|-----------|--------|
| 2 | 张三丰 | 8 | 3 录取 | 0 | student |
| 3 | 李四 | 8 | 3 录取 | 0 | student |
| 4 | 王五 | 8 | 4 驳回 | 0 | student |
| 5 | 王五 | 9 | 1 报名 | **1 软删** | student |
| 6 | 赵六 | 8 | 1 报名 | 0 | student |

> ✅ 三态全部正确：新增落库、更新生效、显式软删落 is_deleted=1；空 data 不再误删其它记录（无全量差异软删）。
